StoryBot Agent Anatomy
Story Retrieval Chatbot · Task 1

How the StoryBot agent works

The agent is a small ReAct loop. An LLM reads the question, decides which story tool to call and with which arguments, reads the tool's JSON result, and repeats until it can answer from what the tools returned. The tools do the actual retrieval: fuzzy matching on titles and genres, then Qdrant lookups and hybrid search.

The components

Six parts, each in its own file under src/storybot/. The agent only talks to the LLM and to the tools; the tools are the only part that touches Qdrant.

Dashed lines: reading the metadata file, and summarize_story asking the same LLM for a summary.

StoryAgent

chat/agent.py. Runs the ReAct loop, keeps a short history of past questions and answers for follow-ups, stops repeated calls, and returns an AgentResult with the answer, every step, and any full stories fetched.

LLM backend

chat/llm.py. One chat(messages, tools) method, two implementations: an OpenAI-compatible endpoint (what you use) and transformers on a GPU. Both return the text plus parsed tool calls.

Prompts

chat/prompts.py. The system prompt holds the rules for choosing tools and parameters (6+ stories for a theme, one story for character questions) and for grounded answers that cite title and id.

StoryTools

chat/tools.py. The 7 tools, their JSON schemas, argument checking and fallbacks. A failing tool returns {"error": ...} as its observation, so the agent can try again instead of crashing.

MetadataMatcher

retrieval/matching.py. Fuzzy-matches what the user typed against titles and genres in story_metadata.json, using your _normalize_title, and returns the original spelling for the Qdrant filter.

StoryRetriever

retrieval/search.py. Reads full stories by id or exact title, and runs hybrid search (ModernBERT late-chunk vectors + BM25, fused with RRF), either grouped by story or restricted to one story.

One turn of the ReAct loop

What happens inside StoryAgent.run(question), in order.

  1. Build the messages. System prompt, the last 4 question/answer pairs (no tool traffic), then the new question.
  2. Ask the LLM with the 7 tool schemas attached. It replies with a Thought: line and one or more tool calls, or with a plain answer.
  3. No tool call? That text is the answer. The loop ends.
  4. Run each tool call through StoryTools.call(name, args). A call identical to an earlier one is not re-run; the agent gets a note to answer or change the arguments.
  5. Append the observation (the tool's JSON, cut at 12,000 characters) as a tool message, and go back to step 2.
  6. After 6 rounds, the agent is told to stop calling tools and answer from what it has.
  7. Return the answer, the trace, and any full stories fetched by id or title. The CLI prints those stories verbatim, so the LLM never has to retype a whole story.
messages = [system, *history[-8:], {"role": "user", "content": question}]
for _ in range(max_steps):                       # 6
    turn = llm.chat(messages, tools=SCHEMAS)     # Thought + tool calls, or an answer
    if not turn.tool_calls:
        return turn.content                      # final answer
    messages.append(assistant_message(turn))
    for call in turn.tool_calls:
        obs = tools.call(call.name, call.arguments)   # JSON dict
        messages.append({"role": "tool", "content": json.dumps(obs)[:12000]})
return llm.chat(messages + [stop_and_answer], tools=None).content

Fuzzy matching, then the Qdrant filter

Used by every tool that takes a title or a genre.

1
Normalise the input with _normalize_title: lowercase, no punctuation, single spaces. The keys in story_metadata.json were written the same way.
2
An exact key match scores 100. Otherwise each title or genre is scored with RapidFuzz as the higher of ratio and token_sort_ratio, which tolerates typos and word order. Partial-substring scoring is not used, so “the night” does not match a long title that contains it.
3
At or above the threshold (85 for titles, 80 for genres), take the original title or genre from the metadata and filter Qdrant on it.
4
Below the threshold, fall back to semantic search, and say so in the observation so the agent can tell the user.

Guardrails

Grounded answers

The system prompt allows answers only from tool results, and asks for the title and id of every story mentioned.

Bounded loop

At most 6 tool rounds. A repeated identical call isn't run again. Observations are cut at 12,000 characters.

Errors as observations

Unknown tools, missing arguments and exceptions come back as {"error": ...}, so the agent can correct itself.

Reproducible

Temperature 0 by default, so the same question gives the same tool choices and arguments.
